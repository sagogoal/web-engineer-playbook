# 11. AIの活用

---
## 11.1. プロンプトエンジニアリング
- [ ] **AI-001:** AIに役割（ロール）を与える（例: 「あなたはシニアエンジニアです」）。
- [ ] **AI-002:** 質問の背景や文脈（コンテキスト）を具体的に提供する。
- [ ] **AI-003:** 期待する出力フォーマットを指定する（例: 「JSONで回答して」）。
- [ ] **AI-004:** 制約条件を与える（例: 「〇〇のライブラリは使わずに」）。
- [ ] **AI-005:** Few-shotプロンプティング（いくつかの例を提示する）を実践する。
- [ ] **AI-006:** CoT（Chain of Thought）プロンプティングの考え方を説明できる。
- [ ] **AI-007:** ReAct（Reason-Act）の考え方を説明できる。

---
## 11.2. コーディング支援 (GitHub Copilotなど)
- [ ] **AI-008:** コメントからコードを生成させる。
- [ ] **AI-009:** 既存のコードの処理内容を自然言語で説明させる。
- [ ] **AI-010:** 既存のコードのリファクタリングを提案させる。
- [ ] **AI-011:** 既存のコードのパフォーマンス改善を提案させる。
- [ ] **AI-012:** 複雑な正規表現を生成させる。
- [ ] **AI-013:** SQLクエリを生成させる。
- [ ] **AI-014:** ユニットテストのテストケースを生成させる。
- [ ] **AI-015:** コードスニペットの定型的な部分を補完させる。
- [ ] **AI-016:** 新しいライブラリやフレームワークの基本的な使い方を学習する。

---
## 11.3. レビュー・ドキュメンテーション
- [ ] **AI-017:** AIにコードレビューを依頼し、潜在的なバグや改善点を指摘させる。
- [ ] **AI-018:** AIにプルリクエストの要約を作成させる。
- [ ] **AI-019:** 関数の仕様コメント（Docstring, JSDocなど）を生成させる。
- [ ] **AI-020:** 既存のコードから仕様書やドキュメントの草案を作成させる。
- [ ] **AI-021:** コミットメッセージの提案をさせる。
- [ ] **AI-022:** CHANGELOGの草案を作成させる。

---
## 11.4. エージェント・自動化
- [ ] **AI-023:** MCP（Multi-turn Conversation Protocol）やエージェントの概念を説明できる。
- [ ] **AI-024:** ファイルI/Oやコマンド実行が可能なAIエージェントに、定型的なタスクを依頼する。
  <details>
  <summary>手を動かす</summary>
  - Cursorやエージェント機能を持つツールを使い、「プロジェクト内の`.js`ファイルをすべて`.ts`ファイルにリネームし、`any`型で型定義を追加して」といった複数ステップのタスクを依頼してみる。
  </details>
- [ ] **AI-025:** AIエージェントにE2Eテストシナリオを作成させる。
- [ ] **AI-026:** AIエージェントにWebサイトのアクセシビリティレポートを作成させる。
- [ ] **AI-027:** AIエージェントに簡単なWebサイトの雛形を作成させる。

---
## 11.5. LLMの活用と倫理
- [ ] **AI-028:** LLMのハルシネーション（幻覚）とは何かを説明できる。
- [ ] **AI-029:** AIの生成したコードを鵜呑みにせず、必ず自分でレビュー・テストする。
- [ ] **AI-030:** 機密情報や個人情報をプロンプトに含めてはいけない理由を説明できる。
- [ ] **AI-031:** ファインチューニングとRAG（Retrieval-Augmented Generation）の違いを説明できる。
- [ ] **AI-032:** ベクトルデータベースの役割を説明できる。
- [ ] **AI-033:** LangChainやLlamaIndexなどのライブラリの役割を説明できる。
