# 11. AIの活用

AIを開発プロセスに組み込み、生産性を向上させるためのスキル。
AIを単なる「コード生成機」としてではなく、「優秀なアシスタント」として使いこなし、より創造的な作業に集中することが目標となる。

---

## AI-001 プロンプトエンジニアリング

### ゴール

AIの能力を最大限に引き出すために、明確、具体的、かつ文脈に沿った指示（プロンプト）を作成できる。

### 完了条件

- [ ] `artifacts` フォルダに成果物を作成する
  - [ ] `README.md`
  - [ ] `anki.csv`
  - [ ] `sample/`

### 実務での思考プロセス

- **役割（Role）** を与えているか？（「あなたはシニアWebエンジニアです」）
- **文脈（Context）** を十分に提供しているか？（コードスニペット、目的、制約など）
- **指示（Instruction）** は明確で具体的か？（曖昧な表現を避ける）
- **フォーマット（Format）** を指定しているか？（JSON, Markdown, etc.）
- **制約（Constraint）** を伝えているか？（「〇〇のライブラリは使わないでください」「日本語で回答してください」）
- **良い例（Few-shot）** を提示しているか？

## AI-002 AIによるコードレビュー

### ゴール

AI（GitHub Copilot, Claudeなど）を活用して、コードレビューの効率化と品質向上を図ることができる。

### 完了条件

- [ ] `artifacts` フォルダに成果物を作成する
  - [ ] `README.md`
  - [ ] `anki.csv`
  - [ ] `sample/`

### 実務での思考プロセス

- **何を確認させるか**？
  - バグの可能性
  - パフォーマンスの懸念
  - セキュリティ脆弱性
  - コーディング規約の遵守
  - 可読性・保守性の改善提案
- **どのように依頼するか**？
  - プルリクエストの差分を貼り付け、「このコードをレビューしてください」と依頼する。
  - プロジェクトのコーディング規約や設計思想を事前に伝えておくと、より的確なレビューが得られる。
- **注意点**:
  - AIの指摘は**鵜呑みにしない**。必ず自分で意図を理解し、妥当性を判断する。
  - AIは最終的な**意思決定者ではない**。あくまで判断材料を提供するアシスタントである。

## AI-003 エージェントの活用 (MCP)

### ゴール

複数のツールを自律的に連携させるAIエージェント（Multi-turn Conversation Protocol）の概念を理解し、定型的な開発タスクの自動化に活用できる。

### 完了条件

- [ ] `artifacts` フォルダに成果物を作成する
  - [ ] `README.md`
  - [ ] `anki.csv`
  - [ ] `sample/`

### 実務での思考プロセス

- どのようなタスクを**自動化**できるか？
  - 新しいAPIエンドポイントの追加（Controller, Service, Repositoryの雛形作成）
  - E2Eテストのシナリオ作成と実行
  - 依存ライブラリの脆弱性チェックとアップデート提案
- **エージェントへの指示**はどのように行うか？
  - 自然言語で最終的なゴールを伝える。（例：「ユーザー作成APIを追加して」）
- **エージェントの思考プロセス**を監視できるか？
  - どのようなコマンドを実行し、どのような判断を下しているかを確認する。
- **権限管理**は適切か？
  - エージェントに与える権限（ファイル書き込み、コマンド実行など）を最小限に留める。
