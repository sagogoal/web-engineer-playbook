# 11. AIの活用

---
## 11.1. プロンプトエンジニアリング
- [ ] **AI-001:** AIに役割（ロール）を与える（例: 「あなたはシニアエンジニアです」）。
- [ ] **AI-002:** 質問の背景や文脈（コンテキスト）を具体的に提供する。
- [ ] **AI-003:** 期待する出力フォーマットを指定する（例: 「JSONで回答して」）。
- [ ] **AI-004:** 制約条件を与える（例: 「〇〇のライブラリは使わずに」）。
- [ ] **AI-005:** Few-shotプロンプティング（いくつかの例を提示する）を実践する。
- [ ] **AI-006:** CoT（Chain of Thought）プロンプティングの考え方を説明できる。
- [ ] **AI-007:** 「ステップバイステップで考えてください」という指示（Zero-shot CoT）の有効性を確認する。
- [ ] **AI-008:** ReAct（Reason-Act）の考え方を説明できる。
- [ ] **AI-009:** AIに出力させた内容を自己評価・自己修正させるプロンプトを記述できる。
- [ ] **AI-010:** 複雑なタスクを、より小さなサブタスクに分解してAIに依頼する。
- [ ] **AI-011:** プロンプトテンプレートを作成し、繰り返し利用するタスクの効率を上げる。

## 11.2. コーディング支援 (GitHub Copilotなど)
- [ ] **AI-012:** コメントからコードを生成させる。
- [ ] **AI-013:** 既存のコードの処理内容を自然言語で説明させる。
- [ ] **AI-014:** 既存のコードのリファクタリングを提案させる。
- [ ] **AI-015:** 既存のコードのパフォーマンス改善を提案させる。
- [ ] **AI-016:** コードの責務が大きすぎる場合に、適切なクラスや関数への分割を提案させる。
- [ ] **AI-017:** 複雑な正規表現を生成させる。
- [ ] **AI-018:** SQLクエリ（JOINやウィンドウ関数を含む）を生成させる。
- [ ] **AI-019:** 新しいライブラリやフレームワークの基本的な使い方をコード例と共に学習する。
- [ ] **AI-020:** エラーメッセージを貼り付け、原因と解決策を質問する。
- [ ] **AI-021:** デバッグ中のコードを貼り付け、潜在的なバグの原因を推測させる。

## 11.3. テストとドキュメンテーション
- [ ] **AI-022:** ユニットテストのテストケース（正常系、異常系、境界値）を生成させる。
- [ ] **AI-023:** 既存のテストコードに対するカバレッジ向上のためのテストケースを提案させる。

- [ ] **AI-026:** AIにプルリクエストのタイトルと説明文を作成させる。
- [ ] **AI-027:** 関数の仕様コメント（Docstring, JSDocなど）を生成させる。
- [ ] **AI-028:** 既存のコードから仕様書や技術ドキュメントの草案を作成させる。
- [ ] **AI-029:** Gitのコミットメッセージの提案をさせる。
- [ ] **AI-030:** CHANGELOGの草案を作成させる。

## 11.4. LLMアプリケーション開発
- [ ] **AI-032:** ファインチューニングとRAG（Retrieval-Augmented Generation）の違いと、それぞれのユースケースを説明できる。
- [ ] **AI-033:** LangChainやLlamaIndexなどのオーケストレーションライブラリの役割を説明できる。
- [ ] **AI-034:** テキストをチャンクに分割する際の戦略（文字数、トークン数、再帰的など）を説明できる。
- [ ] **AI-035:** Embeddingモデルを使い、テキストをベクトル化する。
- [ ] **AI-036:** ベクトルデータベースの役割と、代表的なサービス（Pinecone, Milvus, Chromaなど）を3つ以上挙げられる。
- [ ] **AI-037:** ベクトル検索における類似度指標（コサイン類似度など）を説明できる。
- [ ] **AI-038:** 簡単なドキュメント（例: プロジェクトのREADME）をベクトル化して保存し、それに関する質問に答えるRAGの基本フローを実装する。
  <details>
  <summary>手を動かす</summary>
  - 1. ドキュメントをロード, 2. チャンクに分割, 3. Embeddingモデルでベクトル化, 4. ベクトルDBに保存, 5. 質問をベクトル化, 6. 類似チャンクを検索, 7. 検索結果と質問をLLMに渡す、という流れを実装する。
  </details>
- [ ] **AI-039:** OpenAI FunctionsやLangChainのToolsのような、LLM Function Callingの仕組みを説明できる。
- [ ] **AI-040:** 「今日の天気を教える」といった簡単な外部APIを呼び出すFunction（Tool）を定義し、LLMに利用させる。
- [ ] **AI-041:** LLMが出力したJSONがスキーマ定義と一致しているかをバリデーションする。
- [ ] **AI-042:** ストリーミング（Streaming）APIを使い、レスポンスを逐次表示する。
- [ ] **AI-043:** LangSmithやLangFuseといったLLMアプリケーションの監視・デバッグツールの役割を説明できる。

## 11.5. エージェントと自動化
- [ ] **AI-044:** AIエージェントの基本的なアーキテクチャ（ReActフレームワークなど）を説明できる。
- [ ] **AI-045:** ファイルI/Oやコマンド実行が可能なAIエージェントに、定型的なタスクを依頼する。
  <details>
  <summary>手を動かす</summary>
  - Cursorやエージェント機能を持つツールを使い、「プロジェクト内の`.js`ファイルをすべて`.ts`ファイルにリネームし、`any`型で型定義を追加して」といった複数ステップのタスクを依頼してみる。
  </details>
- [ ] **AI-046:** AIエージェントにE2Eテストシナリオを作成・実行させる。
- [ ] **AI-047:** AIエージェントにWebサイトのアクセシビリティレポートを作成させる。
- [ ] **AI-048:** AIエージェントに簡単なWebサイトの雛形を作成させる。
- [ ] **AI-049:** エージェントにカスタムツール（独自のAPIや関数）を提供し、タスク解決能力を拡張する。
- [ ] **AI-050:** 複数の専門エージェント（コーディング担当、テスト担当など）を連携させてタスクを実行するマルチエージェントシステムの概念を説明できる。
- [ ] **AI-051:** Auto-GPTやCrewAIなどのエージェントフレームワークの名前を挙げられる。

## 11.6. 倫理、セキュリティ、ガバナンス
- [ ] **AI-052:** LLMのハルシネーション（幻覚）とは何かを説明できる。
- [ ] **AI-053:** AIの生成したコードを鵜呑みにせず、必ず自分でレビュー・テストする文化の重要性を説明できる。
- [ ] **AI-054:** 機密情報や個人情報をプロンプトに含めてはいけない理由を説明できる。
- [ ] **AI-055:** プロンプトインジェクション攻撃の原理と、その対策（コンテキストと入力の分離など）を説明できる。
- [ ] **AI-056:** LLMにおけるジェイルブレイク（脱獄）とは何かを説明できる。
- [ ] **AI-057:** AIモデルの持つバイアス（社会的、文化的）が、生成物にどう影響するかを説明できる。
- [ ] **AI-058:** AI生成物の著作権やライセンスに関する基本的な注意点を説明できる。
- [ ] **AI-059:** LLM APIの利用コストをモニタリングし、意図しない高額請求を防ぐ方法を説明できる。
- [ ] **AI-060:** 入力トークンと出力トークンのコストの違いを意識したプロンプト設計を説明できる。
- [ ] **AI-061:** Responsible AI（責任あるAI）の基本的な考え方を説明できる。
- [ ] **AI-062:** モデルの出力内容をフィルタリングする（不適切なコンテンツのブロックなど）ガードレールの役割を説明できる。

## 11.8. チームでのAI活用
- [ ] **AI-069:** チーム内で効果的だったプロンプトを共有・管理する仕組みを導入する。
- [ ] **AI-070:** ペアプログラミングならぬ「ペアAIプログラミング」を実践する。
- [ ] **AI-071:** チームのドキュメントをRAGの対象とし、チーム内での質問応答システムを構築する。
- [ ] **AI-072:** CI/CDパイプラインにAIによるコードレビューやサマリー生成を組み込む。
- [ ] **AI-073:** AIツールの利用ガイドライン（セキュリティ、コスト、倫理）をチームで作成する。
- [ ] **AI-074:** AIの活用によって、チームのベロシティや開発者体験がどう変化したかをふりかえる。
- [ ] **AI-075:** 新しいAIツールや論文の情報をチーム内で共有し、学習する機会を設ける。
- [ ] **AI-076:** 非エンジニア（PMやデザイナー）向けに、AIの基本的な使い方やできることをレクチャーする。
- [ ] **AI-077:** プロジェクトのどの部分にAIを適用すれば最も効果的か（ROIが高いか）を議論する。
- [ ] **AI-078:** AIに仕様の曖昧な点を指摘させ、要件定義の質を向上させる。
- [ ] **AI-079:** ユーザーサポートの一次対応にLLMチャットボットを導入する際の勘所を説明できる。
- [ ] **AI-080:** AIの活用を前提とした新しい開発ワークフローを設計・提案する。
