# 00. ルール

このロードマップは、単なる技術知識のリストではありません。
実務でWebエンジニアが価値を提供するために必要な「思考プロセス」と「行動」を体系化し、日々の業務で実践するためのチェックリストです。

## 基本原則

1.  **目的を意識する**: すべてのタスクは、ビジネス上の目的を達成するために存在します。技術選定や実装の前に、まず「なぜこれが必要なのか？」を自問自答してください。
2.  **完璧より完成**: 80%の完成度で素早くリリースし、フィードバックを得ることを優先します。ただし、品質を犠牲にするという意味ではありません。
3.  **シンプルさを追求する**: 複雑なコードはバグの温床です。常に「よりシンプルな解決策はないか？」を考えてください。
4.  **ドキュメントを残す**: 未来の自分や他のチームメンバーのために、設計の意図や判断理由を文章で残します。
5.  **常に学び続ける**: 技術は常に進化します。昨日まで最適だったものが、今日も最適とは限りません。
6.  **Gitでバージョン管理する**: すべての成果物はGitで管理します。「なぜ」この変更を行ったのかが伝わる、分かりやすいコミットメッセージを心がけてください。

## 学習の進め方

1.  **1項目30分**: 各項目は、約30分で集中して学習できる粒度になっています。
2.  **成果物の作成**: 各項目を完了するには、`artifacts`ディレクトリ内に成果物を作成・整理します。これにより、学習の記録がGitリポジトリ内にポートフォリオとして蓄積されます。
    - **成果物フォルダ構成:** `artifacts/{カテゴリ}/{項目ID}_{項目名}/`
    - **`README.md`**: 学んだこと、実務利用シーンを記述。
    - **`sample/`**: サンプルコードや図を格納。
3.  **AIレビュー**: 作成した成果物はAIにレビューを依頼し、フィードバックを元に改善します。
4.  **完了と記録**: レビューが完了したら、`docs/`内の該当項目のチェックボックスを `[x]` にし、行末に完了日を `(YYYY-MM-DD)` の形式で記録します。
5.  **順番は自由**: 自分の興味や現在の業務内容に合わせて、どのカテゴリからでも学習を進めて構いません。

---

このロードマップを完遂したとき、あなたは単なる「コードが書けるエンジニア」ではなく、「ビジネス課題を技術で解決できるエンジニア」へと大きく成長しているはずです。
