# 07. テスト

---
## 7.1. テストの概念・文化
- [ ] **TST-001:** テストピラミッド（Unit, Integration, E2E）の各層の役割を説明できる。
- [ ] **TST-002:** なぜテストを書くのか、その目的（品質保証、デグレ防止、リファクタリングの安心感）を説明できる。
- [ ] **TST-003:** TDD（テスト駆動開発）の「レッド・グリーン・リファクタリング」のサイクルを説明できる。
- [ ] **TST-004:** 「カバレッジ100%」が必ずしも高品質を意味しない理由を説明できる。
- [ ] **TST-005:** 良いテストの特性（A-TRIP: 自動、徹底的、繰り返し可能、独立、プロフェッショナル）を説明できる。

---
## 7.2. 単体テスト (Unit Test)
- [ ] **TST-006:** AAAパターン（Arrange, Act, Assert）に沿ってテストを記述できる。
- [ ] **TST-007:** 純粋関数（同じ入力に対して常に同じ出力を返す関数）の単体テストを記述する。
  <details>
  <summary>手を動かす</summary>
  - 2つの数値を引数に取り、その合計を返す`add(a, b)`関数のテストを、Jestなどのテスティングフレームワークを使って記述する。
  </details>
- [ ] **TST-008:** テストダブル（スタブ、モック、スパイ）の使い分けを説明できる。
- [ ] **TST-009:** Jestを使い、外部依存を持つ関数のテストをモックを使って記述する。
  <details>
  <summary>手を動かす</summary>
  - ユーザーIDを受け取り、`fetchUserAPI(id)`を呼び出してユーザー名を返す`getUserName(id)`関数をテストする。
  - `fetchUserAPI`をモックし、特定のユーザーデータを返すように設定する。
  </details>
- [ ] **TST-010:** 正常系（ハッピーパス）のテストケースを記述できる。
- [ ] **TST-011:** 異常系（エラー、例外）のテストケースを記述できる。
- [ ] **TST-012:** 境界値（0, -1, null, undefined, 空文字）のテストケースを記述できる。
- [ ] **TST-013:** テストの命名規則（`should ... when ...`など）を学ぶ。
- [ ] **TST-014:** `describe`や`it`（`test`）を使い、テストを構造化できる。
- [ ] **TST-015:** Reactコンポーネントの単体テスト（レンダリング、イベント発火）を`React Testing Library`を使って記述する。
  <details>
  <summary>手を動かす</summary>
  - カウンターコンポーネントに対し、「初期表示が0であること」「ボタンクリックで1になること」をテストする。
  </details>
- [ ] **TST-016:** `Date`や`Math.random`など、実行のたびに結果が変わる処理のテスト方法を説明できる。

---
## 7.3. 結合テスト (Integration Test)
- [ ] **TST-017:** 単体テストと結合テストの違いを説明できる。
- [ ] **TST-018:** APIの結合テストで、実際にDBにデータを投入し、APIを叩いて結果を検証するテストを記述する。
- [ ] **TST-019:** テスト用のDBを準備し、各テストの実行前にDBの状態をクリーンにする方法を説明できる。
- [ ] **TST-020:** Supertestなどのライブラリを使い、APIエンドポイントのテストを記述する。
- [ ] **TST-021:** モックサーバー（MSWなど）を使い、フロントエンドとAPIの結合テストを記述する。

---
## 7.4. E2Eテスト (End-to-End Test)
- [ ] **TST-022:** E2Eテストの目的と、ピラミッドの上位に位置する理由（コストが高い）を説明できる。
- [ ] **TST-023:** 主要なユーザーストーリー（ユーザー登録、ログイン、投稿など）をE2Eテストのシナリオとして記述する。
- [ ] **TST-024:** CypressやPlaywrightなどのE2Eテストフレームワークの特徴を説明できる。
- [ ] **TST-025:** Cypressを使い、ログイン画面のE2Eテストを記述する。
  <details>
  <summary>手を動かす</summary>
  - テスト用のWebページにアクセスし、ユーザー名とパスワードを入力し、ログインボタンをクリックし、特定のページに遷移したことをアサートするテストコードを記述する。
  </details>
- [ ] **TST-026:** E2Eテストにおける`wait`の扱い（アンチパターン）と、アサーションによる待機の重要性を説明できる。
- [ ] **TST-027:** テストの独立性を保つために、E2Eテストの前にDBの状態をリセットする。

## 7.6. 品質とメトリクス
- [ ] **TST-036:** コードカバレッジ（Line, Branch, Function）のそれぞれの意味を説明できる。
- [ ] **TST-037:** 静的解析ツール（Linter）をテストプロセスに組み込むメリットを説明できる。
- [ ] **TST-038:** 循環的複雑度（Cyclomatic Complexity）とは何かを説明できる。
- [ ] **TST-039:** バグトラッキングシステム（Jira, Redmineなど）の基本的な使い方を説明できる。
- [ ] **TST-040:** バグレポートに書くべき項目（再現手順、期待する結果、実際の結果、環境）を説明できる。
- [ ] **TST-041:** QA（品質保証）エンジニアの役割を説明できる。
- [ ] **TST-042:** 受け入れテスト（UAT）の目的を説明できる。
- [ ] **TST-043:** リグレッションテスト（回帰テスト）の重要性を説明できる。
- [ ] **TST-044:** スモークテストの目的を説明できる。
- [ ] **TST-045:** Flaky Test（不安定なテスト）がなぜ問題になるか説明できる。
- [ ] **TST-046:** テストダブルの使いすぎによる弊害（過剰なモック）を説明できる。
- [ ] **TST-047:** BDD（振る舞い駆動開発）とTDDの違いを説明できる。
- [ ] **TST-048:** Gherkin（Given-When-Then）を使ったテストシナリオを記述する。
- [ ] **TST-049:** 探索的テストの基本的な考え方を説明できる。
- [ ] **TST-050:** テスト計画書に記載すべき項目を説明できる。
