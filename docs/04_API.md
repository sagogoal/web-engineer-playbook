# 04. API

---
## 4.1. RESTの基本原則
- [ ] **API-001:** RESTがアーキテクチャスタイルの一種であることを説明できる。
- [ ] **API-002:** 「リソース」中心の設計とは何かを説明できる。
- [ ] **API-003:** URIが「名詞」で表現されるべき理由を説明できる。
- [ ] **API-004:** HTTPメソッド（GET, POST, PUT, DELETE, PATCH）の役割と冪等性を説明できる。
- [ ] **API-005:** `PUT`と`PATCH`の違いを説明できる。
- [ ] **API-006:** ステートレス性とは何か、なぜ重要なのかを説明できる。
- [ ] **API-007:** HATEOAS (Hypermedia as the Engine of Application State) の概念を説明できる。

---
## 4.2. URI設計
- [ ] **API-008:** URIに複数形の名詞を使う（例: `/users`）。
- [ ] **API-009:** URIでリソースの階層関係を表現する（例: `/users/{userId}/posts`）。
- [ ] **API-010:** URIの単語の区切り文字としてハイフン `-` を使う。
- [ ] **API-011:** URIにプログラミング言語の拡張子（`.php`など）を含めない。
- [ ] **API-012:** APIのバージョン管理戦略（URI、ヘッダー）のメリット・デメリットを説明できる。

---
## 4.3. リクエスト設計
- [ ] **API-013:** パスパラメータ、クエリパラメータ、リクエストボディの使い分けを説明できる。
- [ ] **API-014:** `GET` の一覧取得APIで、ページネーションのためのクエリパラメータを設計する（`page`, `per_page`など）。
- [ ] **API-015:** `GET` の一覧取得APIで、ソートのためのクエリパラメータを設計する（`sort`, `order`など）。
- [ ] **API-016:** `GET` の一覧取得APIで、フィルタリングのためのクエリパラメータを設計する（`status=published`など）。
- [ ] **API-017:** `POST` でリソースを作成する際のリクエストボディ（JSON）を設計する。
- [ ] **API-018:** HTTPヘッダー（`Content-Type`, `Accept`, `Authorization`）の役割を説明できる。

---
## 4.4. レスポンス設計
- [ ] **API-019:** HTTPステータスコードのカテゴリ（2xx, 3xx, 4xx, 5xx）を説明できる。
- [ ] **API-020:** `200 OK`, `201 Created`, `204 No Content` の使い分けを説明できる。
- [ ] **API-021:** `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found` の使い分けを説明できる。
- [ ] **API-022:** 成功時のレスポンスボディをJSONで設計する（データ本体を`data`キーでラップするなど）。
- [ ] **API-023:** 失敗時のエラーレスポンスの共通フォーマット（RFC 7807準拠など）を設計する。
- [ ] **API-024:** バリデーションエラーの際に、どの項目がなぜエラーなのかを具体的に返すレスポンスを設計する。
- [ ] **API-025:** レスポンスの命名規則として `camelCase` を採用する。

---
## 4.5. APIセキュリティ (認証・認可)
- [ ] **API-026:** 認証（Authentication）と認可（Authorization）の違いを明確に説明できる。
- [ ] **API-027:** APIキーを使った認証方式の仕組みを説明できる。
- [ ] **API-028:** セッション認証の仕組みを説明できる。
- [ ] **API-029:** JWT（JSON Web Token）の構造（ヘッダー、ペイロード、署名）を説明できる。
- [ ] **API-030:** JWTの署名を検証する流れを説明できる。
- [ ] **API-031:** JWTのペイロードに含めるべき情報（`iss`, `sub`, `exp`など）を説明できる。
- [ ] **API-032:** JWTのメリット（ステートレス性）とデメリット（失効が難しい）を説明できる。
- [ ] **API-033:** OAuth 2.0がどのような問題を解決するためのものか説明できる（認可の委譲）。
- [ ] **API-034:** OAuth 2.0の登場人物（リソースオーナー、クライアント、認可サーバー、リソースサーバー）を説明できる。
- [ ] **API-035:** OAuth 2.0の代表的なフロー（認可コードフロー）の概要を説明できる。
- [ ] **API-036:** PKCE (Proof Key for Code Exchange) がなぜ必要なのか説明できる。
- [ ] **API-037:** アクセストークンとリフレッシュトークンの役割の違いを説明できる。
- [ ] **API-038:** OpenID Connect (OIDC) とOAuth 2.0の違いを説明できる。
- [ ] **API-039:** CORS（オリジン間リソース共有）エラーが発生する原因を説明できる。
- [ ] **API-040:** サーバー側でCORSを許可するためのHTTPヘッダー（`Access-Control-Allow-Origin`）を説明できる。
- [ ] **API-041:** プリフライトリクエスト（`OPTIONS`メソッド）が発行される条件を説明できる。
- [ ] **API-042:** レートリミットの必要性を説明できる。
- [ ] **API-043:** リクエスト内容のバリデーションがなぜセキュリティ上重要なのかを説明できる。
- [ ] **API-044:** RBAC（ロールベースアクセス制御）とABAC（属性ベースアクセス制御）の基本的な考え方を説明できる。

---
## 4.6. パフォーマンスと信頼性
- [ ] **API-045:** コンテントネゴシエーション（`Accept`ヘッダー）の仕組みを説明できる。
- [ ] **API-046:** HTTP/1.1, HTTP/2, HTTP/3の主な違いを説明できる。
- [ ] **API-047:** BFF（Backend For Frontend）アーキテクチャのAPI設計における役割を説明できる。
- [ ] **API-048:** `If-None-Match`や`Etag`を使ったHTTPキャッシュの仕組みを説明できる。
- [ ] **API-049:** APIの冪等性を保証するための具体的な設計パターン（冪等キーなど）を説明できる。
- [ ] **API-050:** APIのメトリクス（リクエスト数、レイテンシ、エラーレート）を監視する重要性を説明できる。
- [ ] **API-051:** APIゲートウェイの役割（ルーティング、認証、レートリミットなど）を説明できる。
- [ ] **API-052:** クライアント側のサーキットブレーカーパターンの役割を説明できる。
- [ ] **API-053:** Dry-run（ドライラン）をサポートするAPIを設計する（`X-Dry-Run`ヘッダーなど）。

## 4.7. GraphQL
- [ ] **API-054:** GraphQLがRESTと比べてどのようなメリットがあるか説明できる（オーバーフェッチ/アンダーフェッチ問題の解決）。
- [ ] **API-055:** GraphQLスキーマ定義言語（SDL）を使い、型を定義する。
- [ ] **API-056:** Query（クエリ）とMutation（ミューテーション）の違いを説明できる。
- [ ] **API-057:** リゾルバ（Resolver）の役割を説明できる。
- [ ] **API-058:** GraphQLにおけるN+1問題と、DataLoaderを使った解決策を説明できる。
- [ ] **API-059:** Subscription（サブスクリプション）を使い、リアルタイムなデータ更新を実現する方法を説明できる。
- [ ] **API-060:** GraphQLスキーマのページネーション設計（Cursor-based）を説明できる。
- [ ] **API-061:** GraphQL FederationやSchema Stitchingといった、スキーマを分割・統合する技術を説明できる。

---
## 4.8. gRPC
- [ ] **API-062:** gRPCの概要と、RESTとの違い（HTTP/2, Protocol Buffers）を説明できる。
- [ ] **API-063:** Protocol Buffersでメッセージとサービスを定義する`.proto`ファイルを記述する。
- [ ] **API-064:** gRPCの4つの通信方式（Unary, Server streaming, Client streaming, Bidirectional streaming）を説明できる。
- [ ] **API-065:** gRPCのInterceptor（Middleware）を使い、共通処理を実装する方法を説明できる。
- [ ] **API-066:** gRPCのエラーハンドリングと、標準的なエラーステータスコードを説明できる。
- [ ] **API-067:** gRPCのDeadline（タイムアウト）の重要性と設定方法を説明できる。
- [ ] **API-068:** gRPC-GatewayやgRPC-Webの役割（ブラウザからのgRPC利用）を説明できる。

## 4.9. 非同期APIとイベント駆動

- [ ] **API-070:** Webhookリクエストの署名を検証し、送信元が正当であることを確認する。
- [ ] **API-071:** 長時間かかる処理をAPIで受け付ける際の非同期処理パターン（ポーリング、Webhook）を設計する。
- [ ] **API-072:** WebSocketを使った双方向通信のユースケースを説明できる。
- [ ] **API-073:** ロングポーリングの仕組みと、WebSocketとの違いを説明できる。
- [ ] **API-074:** AsyncAPI仕様の役割と、イベント駆動アーキテクチャのドキュメンテーションにおける重要性を説明できる。
