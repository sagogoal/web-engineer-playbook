開発したアプリケーションを、ユーザーが利用できる本番環境に展開するプロセス。
手作業を排し、CI/CDパイプラインを通じて自動化、高速化、安全性を確保することが目標となる。

## DPL-003 リリース戦略

### ゴール

デプロイに伴うリスクを管理し、ユーザーへの影響を最小限に抑えるための様々なリリース戦略（ブルー/グリーン、カナリアなど）を説明できる。

### 完了条件

- [ ] `artifacts` フォルダに成果物を作成する
  - [ ] `README.md`
  - [ ] `anki.csv`
  - [ ] `sample/`

### 実務での思考プロセス

- **Blue/Green Deployment**:
  - 概要: 新旧2つの環境を用意し、ロードバランサーで一気に切り替える。
  - メリット: 即時ロールバックが可能。
  - デメリット: インフラコストが2倍かかる。
- **Canary Release**:
  - 概要: 新バージョンを一部のユーザーにだけ公開し、問題がなければ徐々に展開する。
  - メリット: リスクを最小限に抑えられる。
  - デメリット: 管理が複雑。
- **Feature Flag (Feature Toggle)**:
  - 概要: コード内に新機能のON/OFFを切り替えるフラグを埋め込み、リリース後に有効化する。
  - メリット: デプロイとリリースの分離。
  - デメリット: コードが複雑になる。
- 現在のプロジェクトではどの戦略が採用されているか？それはなぜか？
