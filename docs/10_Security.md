# 10. セキュリティ

---
## 10.1. セキュア開発ライフサイクル (Shift-Left)
- [ ] **SEC-001:** セキュア開発ライフサイクル（SDLC）の重要性を説明できる。
- [ ] **SEC-002:** 脅威モデリングの基本的な考え方（STRIDEなど）を説明できる。
- [ ] **SEC-003:** 設計段階でセキュリティリスクを洗い出し、対策を検討する。
- [ ] **SEC-004:** 最小権限の原則を説明できる。
- [ ] **SEC-005:** フェイルセーフとフールプルーフの考え方を説明できる。
- [ ] **SEC-006:** ゼロトラストアーキテクチャの基本的な考え方を説明できる。
- [ ] **SEC-007:** 静的解析（SAST）と動的解析（DAST）の違いを説明できる。
- [ ] **SEC-008:** IAST（Interactive Application Security Testing）の仕組みを説明できる。
- [ ] **SEC-009:** CI/CDパイプラインにSASTツール（Snyk, Semgrepなど）を組み込む。
- [ ] **SEC-010:** Git-secretsなどのツールを使い、誤ってシークレットをコミットしないように設定する。

---
## 10.2. アプリケーション脆弱性 (OWASP Top 10)
- [ ] **SEC-011:** OWASP Top 10の最新版の項目を5つ以上挙げられる。
- [ ] **SEC-012:** XSS（クロスサイトスクリプティング）の3種類（Stored, Reflected, DOM-based）の違いを説明できる。
- [ ] **SEC-013:** XSSの対策（エスケープ処理、CSP）を実装できる。
- [ ] **SEC-014:** CSRF（クロスサイトリクエストフォージェリ）の脆弱性の原理と対策（CSRFトークン, SameSite属性）を説明できる。
- [ ] **SEC-015:** SQLインジェクションの脆弱性の原理と対策（プレースホルダ）を説明できる。
- [ ] **SEC-016:** OSコマンドインジェクションの脆弱性の原理と対策（外部コマンド呼び出しの回避）を説明できる。
- [ ] **SEC-017:** ディレクトリトラバーサルの脆弱性の原理と対策（入力の無害化）を説明できる。
- [ ] **SEC-018:** SSRF（サーバーサイドリクエストフォージェリ）の脆弱性の原理と対策（許可リストベースの宛先検証）を説明できる。
- [ ] **SEC-019:** オープンリダイレクトの脆弱性の原理と対策（リダイレクト先の検証）を説明できる。
- [ ] **SEC-020:** 安全でないデシリアライゼーションの脆弱性を説明できる。
- [ ] **SEC-021:** XXE（XML外部実体参照）攻撃の脆弱性を説明できる。
- [ ] **SEC-022:** Insecure Design（安全でない設計）の具体例を挙げられる。
- [ ] **SEC-023:** Security Misconfiguration（セキュリティ設定の不備）の具体例を挙げられる。
- [ ] **SEC-024:** 脆弱性診断ツール（OWASP ZAPなど）を使い、ローカルのアプリケーションをスキャンしてみる。

---
## 10.3. 認証とセッション管理
- [ ] **SEC-025:** Cookieとセッションの仕組みを説明できる。
- [ ] **SEC-026:** Cookieの属性（`Secure`, `HttpOnly`, `SameSite`）の役割を説明できる。
- [ ] **SEC-027:** `SameSite`属性の`Strict`, `Lax`, `None`の違いを説明できる。
- [ ] **SEC-028:** セッション固定化（Session Fixation）攻撃の原理と対策を説明できる。
- [ ] **SEC-029:** パスワードのハッシュ化とソルト、ペッパーの重要性を説明できる。
- [ ] **SEC-030:** 多要素認証（MFA）の必要性を説明できる。
- [ ] **SEC-031:** TOTP（時間ベースのワンタイムパスワード）の仕組みを説明できる。
- [ ] **SEC-032:** ログイン機能のブルートフォース攻撃対策（アカウントロック、CAPTCHA）を実装できる。
- [ ] **SEC-033:** クレデンシャルスタッフィング攻撃の概要を説明できる。
- [ ] **SEC-034:** 安全なパスワードリセット機能の設計ポイントを説明できる。

---
## 10.4. 通信とネットワーク
- [ ] **SEC-035:** HTTPS（SSL/TLS）が提供する価値（暗号化、改ざん検知、認証）を説明できる。
- [ ] **SEC-036:** HTTP Strict Transport Security (HSTS) ヘッダーの役割を説明できる。
- [ ] **SEC-037:** Content Security Policy (CSP) ヘッダーの役割と、基本的なディレクティブを説明できる。
- [ ] **SEC-038:** クリックジャッキングの脆弱性の原理と対策（`X-Frame-Options`ヘッダー）を説明できる。
- [ ] **SEC-039:** CORS（オリジン間リソース共有）の仕組みをセキュリティの観点から説明できる。
- [ ] **SEC-040:** DoS/DDoS攻撃の概要と、その対策（レートリミット、CDN）を説明できる。
- [ ] **SEC-041:** WAF（Web Application Firewall）の役割と、シグネチャベース/スコアベースの違いを説明できる。
- [ ] **SEC-042:** ポートスキャンの概要を説明できる。
- [ ] **SEC-043:** サブドメインテイクオーバーの脆弱性を説明できる。

---
## 10.5. サプライチェーンセキュリティ
- [ ] **SEC-044:** サプライチェーン攻撃の概要を説明できる。
- [ ] **SEC-045:** `npm audit`や`dependabot`を使い、依存ライブラリの脆弱性をチェックし、修正する。
- [ ] **SEC-046:** `package-lock.json`や`yarn.lock`がなぜ重要かをセキュリティの観点から説明できる。
- [ ] **SEC-047:** ソフトウェア部品表（SBOM）の目的を説明できる。
- [ ] **SEC-048:** SLSA（Supply-chain Levels for Software Artifacts）フレームワークの目的を説明できる。
- [ ] **SEC-049:** Sigstoreの役割（ソフトウェア署名と検証）を説明できる。
- [ ] **SEC-050:** typo-squatting（タイポスクワッティング）による悪意のあるパッケージの危険性を説明できる。

---
## 10.6. クラウドセキュリティ (AWS例)
- [ ] **SEC-051:** IAMのベストプラクティス（最小権限、ルートユーザーのMFA、アクセスキーの定期的なローテーション）を説明できる。
- [ ] **SEC-052:** セキュリティグループとネットワークACL（NACL）の違いを説明できる。
- [ ] **SEC-053:** S3バケットのセキュリティ設定（パブリックアクセスのブロック、暗号化、バージョニング）を確認・設定できる。
- [ ] **SEC-054:** AWS WAFを使い、SQLインジェクションやXSSからアプリケーションを保護するルールを設定する。
- [ ] **SEC-055:** Secrets ManagerやParameter Storeを使って、シークレット情報を安全に管理する。
- [ ] **SEC-056:** GuardDutyの役割（脅威検知サービス）を説明できる。
- [ ] **SEC-057:** CloudTrailの役割（APIアクティビティのロギング）と、監査への活用方法を説明できる。
- [ ] **SEC-058:** VPC Flow Logsを有効化し、VPC内のIPトラフィックを監視する方法を学ぶ。
- [ ] **SEC-059:** 共有責任モデル（Shared Responsibility Model）について説明できる。

---
## 10.7. コンテナセキュリティ
- [ ] **SEC-060:** Dockerイメージの脆弱性スキャンツール（Trivy, Snykなど）をCI/CDに組み込む。
- [ ] **SEC-061:** distrolessイメージやalpineベースのイメージを使い、コンテナの攻撃対象領域（Attack Surface）を削減する。
- [ ] **SEC-062:** Dockerコンテナをroot以外のユーザーで実行する。
- [ ] **SEC-063:** Dockerfileのセキュリティベストプラクティス（`COPY`より`ADD`を避けるなど）を適用する。
- [ ] **SEC-064:** コンテナランタイムセキュリティツール（Falcoなど）の役割を説明できる。
- [ ] **SEC-065:** KubernetesのRBAC（Role-Based Access Control）を設定し、ユーザーやPodの権限を制限する。
- [ ] **SEC-066:** KubernetesのPod Security Policy（または後継のPod Security Admission）の役割を説明できる。
- [ ] **SEC-067:** コンテナレジストリ（ECRなど）の脆弱性スキャン機能を有効化する。
- [ ] **SEC-068:** コンテナのシークレット管理（Kubernetes Secrets, Vaultなど）の方法を説明できる。

---
## 10.8. インシデント対応とプライバシー
- [ ] **SEC-069:** セキュリティインシデント発生時の初動対応（報告、影響範囲の確認、封じ込め）を説明できる。
- [ ] **SEC-070:** ログ分析を行い、不正アクセスの痕跡（不審なIPアドレス、予期せぬAPIコールなど）を調査する。
- [ ] **SEC-071:** デジタルフォレンジックの基本的な考え方を説明できる。
- [ ] **SEC-072:** セキュリティインシデント後の事後対応（原因分析、再発防止策の策定）の重要性を説明できる。
- [ ] **SEC-073:** 個人情報（PII）を扱う際の注意点を説明できる。
- [ ] **SEC-074:** GDPRやCCPAなどのプライバシー保護規制の基本的な概念を説明できる。
- [ ] **SEC-075:** データ暗号化（保管時、転送時）の重要性を説明できる。
- [ ] **SEC-076:** ペネトレーションテスト（侵入テスト）の目的と進め方を説明できる。
- [ ] **SEC-077:** バグ報奨金制度（Bug Bounty Program）の目的を説明できる。
- [ ] **SEC-078:** セキュリティに関する情報を収集するための情報源（JVN, OWASP, 著名なセキュリティブログなど）を3つ以上挙げられる。
- [ ] **SEC-079:** ハードニングの考え方を説明できる。
- [ ] **SEC-080:** 定期的なセキュリティアップデート（パッチ適用）の重要性を説明できる。
