# 09. 運用・監視

---
## 9.1. モニタリング
- [ ] **OPS-001:** モニタリングの4つのゴールデンシグナル（レイテンシー, トラフィック, エラー, 彩度）を説明できる。
- [ ] **OPS-002:** USEメソッド（Utilization, Saturation, Errors）とREDメソッド（Rate, Errors, Duration）を説明できる。
- [ ] **OPS-003:** SLI（サービスレベル指標）、SLO（サービスレベル目標）、SLA（サービスレベル合意）の違いを説明できる。
- [ ] **OPS-004:** ユーザー登録機能のSLIとして「APIの成功率」と「レスポンスタイム（99パーセンタイル）」を設定し、具体的なSLO（例: 99.9%）を定義する。
- [ ] **OPS-005:** ホワイトボックスモニタリングとブラックボックスモニタリングの違いを説明できる。
- [ ] **OPS-006:** 外形監視（ブラックボックス監視）ツール（UptimeRobot, Pingdomなど）を使い、Webサイトの死活監視を設定する。
- [ ] **OPS-007:** シンセティック監視を使い、主要なユーザーストーリー（ログイン〜商品購入など）が正常に機能しているかを定期的にテストする。
- [ ] **OPS-008:** RUM（Real User Monitoring）とシンセティック監視の違いを説明できる。
- [ ] **OPS-009:** 監視ツール（Datadog, CloudWatchなど）を使い、CPU使用率やメモリ使用量のメトリクスをダッシュボードで可視化する。
- [ ] **OPS-010:** アプリケーションのカスタムメトリクス（例: ユーザー登録数、購入数）を送信するコードを記述する。
- [ ] **OPS-011:** ダッシュボードを作成する際のベストプラクティス（目的を明確にする、見るべき指標を絞るなど）を説明できる。

---
## 9.2. アラート
- [ ] **OPS-012:** アラートの閾値設定の難しさ（アラート疲れ）と、その対策（Symphony-based alertingなど）を説明できる。
- [ ] **OPS-013:** CPU使用率が80%を5分間超えたらアラートが飛ぶ、という設定を監視ツールで行う。
- [ ] **OPS-014:** 統計的な異常検知（Anomaly Detection）アラートの仕組みとメリットを説明できる。
- [ ] **OPS-015:** 複数のアラートをまとめて通知する仕組み（アラートのグルーピング）の重要性を説明できる。
- [ ] **OPS-016:** アラートの通知先（メール、Slack、PagerDutyなど）を適切に設定する。
- [ ] **OPS-017:** 対応不要なアラート（flapping, noisy alert）を特定し、定期的に見直して改善する。
- [ ] **OPS-018:** エラーバジェットの残量に基づいてアラートを発報する設定を検討できる。

---
## 9.3. ロギング
- [ ] **OPS-019:** ログレベル（DEBUG, INFO, WARN, ERROR, FATAL）の使い分けを説明できる。
- [ ] **OPS-020:** 構造化ロギングのメリットを説明できる。
- [ ] **OPS-021:** 構造化ログ（JSON形式）を出力する。
  <details>
  <summary>手を動かす</summary>
  - 任意のロギングライブラリを使い、`{ "level": "INFO", "message": "User logged in", "user_id": 123 }` のようなログを出力するコードを記述する。
  </details>
- [ ] **OPS-022:** ログにトレースID（リクエストID）を含める重要性を説明できる。
- [ ] **OPS-023:** ログ集約基盤（Fluentd, Elasticsearch(OpenSearch), Lokiなど）のアーキテクチャを説明できる。
- [ ] **OPS-024:** ログ検索ツール（Kibana, Grafanaなど）を使い、特定のエラーログを検索・フィルタリングする。
- [ ] **OPS-025:** ログから特定のメトリクス（例: エラーレート）を生成する方法を説明できる。
- [ ] **OPS-026:** ログに出力してはいけない情報（個人情報、パスワード、クレデンシャルなど）と、そのマスキング方法を説明できる。
- [ ] **OPS-027:** アプリケーションログ、アクセスログ、スロークエリログ、監査ログの違いを説明できる。
- [ ] **OPS-028:** 大量ログによるコスト増やパフォーマンスへの影響を考慮し、ログのサンプリングを検討できる。

---
## 9.4. 分散トレーシング
- [ ] **OPS-029:** 分散トレーシングが解決する課題（マイクロサービスにおけるリクエストの追跡）を説明できる。
- [ ] **OPS-030:** トレース、スパン、親子関係、コンテキスト伝播の概念を説明できる。
- [ ] **OPS-031:** OpenTelemetryの役割と、それがベンダーロックインをどう防ぐのか説明できる。
- [ ] **OPS-032:** W3C Trace Contextの仕様について説明できる。
- [ ] **OPS-033:** JaegerやZipkinなどの分散トレーシングシステムの役割を説明できる。
- [ ] **OPS-034:** 自動計装（Auto-instrumentation）と手動計装（Manual-instrumentation）の違いを説明できる。
- [ ] **OPS-035:** 簡単なAPI呼び出しにトレースを計装し、リクエストのボトルネックを可視化する。
- [ ] **OPS-036:** トレースデータのサンプリング戦略（Head-based, Tail-based）の違いを説明できる。
- [ ] **OPS-037:** スパンに業務的に意味のある属性（`user.id`など）を追加する。

---
## 9.5. 障害対応 (インシデント管理)
- [ ] **OPS-038:** 障害発生時の一次対応（切り分け、影響範囲の特定、関係者への連絡）をシミュレーションできる。
- [ ] **OPS-039:** ログやメトリクスを見て、障害の原因を調査する。
- [ ] **OPS-040:** ワークアラウンド（応急処置）と恒久対応の違いを説明できる。
- [ ] **OPS-041:** インシデント管理における役割（インシデントコマンダー、コミュニケーションリードなど）を説明できる。
- [ ] **OPS-042:** 障害対応時のコミュニケーションの重要性（事実と推測を分けるなど）を説明できる。
- [ ] **OPS-043:** ポストモーテム（障害ふりかえり）の目的と、「非難しない文化（Blameless Post-mortem）」の重要性を説明できる。
- [ ] **OPS-044:** ポストモーテムに記載すべき項目（タイムライン、根本原因、再発防止策）を挙げられる。
- [ ] **OPS-045:** 「なぜなぜ分析」を使い、障害の根本原因を深掘りする。
- [ ] **OPS-046:** 再発防止策（アクションアイテム）の担当者と期限を決め、追跡する。
- [ ] **OPS-047:** Runbook（プレイブック）の目的と、良いRunbookの特性を説明できる。
- [ ] **OPS-048:** 定期的に発生するアラート対応の手順をRunbookとしてドキュメント化する。
- [ ] **OPS-049:** Game Day（障害対応訓練）の目的と進め方を説明できる。

---
## 9.6. SRE (Site Reliability Engineering)
- [ ] **OPS-050:** SREの基本的な考え方（「信頼性は機能である」）を説明できる。
- [ ] **OPS-051:** エラーバジェットの概念を説明し、SLO違反が開発プロセスにどう影響するかを説明できる。
- [ ] **OPS-052:** Toil（手作業、自動化可能、戦術的など）の定義を説明できる。
- [ ] **OPS-053:** 自身の業務の中からToilを特定し、その自動化方法を提案する。
- [ ] **OPS-054:** On-call（オンコール）体制の目的と、持続可能なオンコール運用のためのプラクティスを説明できる。
- [ ] **OPS-055:** カオスエンジニアリングの目的と、それがシステムの堅牢性をどう向上させるかを説明できる。
- [ ] **OPS-056:** キャパシティプランニングの重要性と、基本的な進め方を説明できる。
- [ ] **OPS-057:** 需要予測に基づき、将来必要なリソース（CPU, メモリ, ストレージ）を見積もる。
- [ ] **OPS-058:** 本番環境への変更に対するリスク評価（ピアレビュー、段階的リリースなど）の重要性を説明できる。
- [ ] **OPS-059:** SREと従来の運用チーム、DevOpsとの違いを説明できる。

---
## 9.7. コスト管理
- [ ] **OPS-060:** クラウドのコスト管理の重要性を説明できる。
- [ ] **OPS-061:** AWS Cost ExplorerやGCPの請求レポートなどを使い、現在のクラウド利用費の内訳を確認する。
- [ ] **OPS-062:** リソースに適切なタグを付与し、プロジェクトやチームごとのコストを可視化する。
- [ ] **OPS-063:** ライトサイジング（インスタンスタイプの最適化）の考え方を説明できる。
- [ ] **OPS-064:** スケールイン/スケールアウトの設定を最適化し、不要なコストを削減する方法を検討する。
- [ ] **OPS-065:** 予約インスタンス（RI）やSavings Plansのメリット・デメリットを説明できる。
- [ ] **OPS-066:** スポットインスタンスのユースケースと注意点を説明できる。
- [ ] **OPS-067:** ストレージクラス（標準、低頻度アクセスなど）を使い分け、ストレージコストを最適化する。
- [ ] **OPS-068:** FinOpsの基本的な考え方を説明できる。

## 9.8. その他
- [ ] **OPS-069:** 技術サポートへの問い合わせ（起票）の際に含めるべき情報（事象、再現手順、環境、試したこと）を説明できる。
- [ ] **OPS-070:** システムの定期メンテナンス（OSアップデート、ライブラリ更新）の計画を立てる。
- [ ] **OPS-071:** データバックアップ・リストアの手順を定期的にテストする。
- [ ] **OPS-072:** パフォーマンスのボトルネックを特定するためのプロファイリングツールの使い方を学ぶ。
- [ ] **OPS-073:** DNSのTTL（Time To Live）がシステムの可用性にどう影響するかを説明できる。
- [ ] **OPS-074:** CDNのキャッシュヒット率を監視し、改善する方法を検討する。
- [ ] **OPS-075:** SLO Violation（SLO違反）が継続した場合のエスカレーションパスを定義する。
- [ ] **OPS-076:** データベースのコネクションプールの状態（アクティブ、アイドル）を監視する。
- [ ] **OPS-077:** Feature Flagの運用（棚卸し、削除）について説明できる。
- [ ] **OPS-078:** プロダクトのEOL（End-of-Life）や非推奨（deprecation）ポリシーの重要性を説明できる。
- [ ] **OPS-079:** 外部サービスの障害情報を追跡する（ステータスページの購読など）。
- [ ] **OPS-080:** KubernetesにおけるPodのヘルスチェック（Liveness/Readiness Probe）の役割を説明できる。
