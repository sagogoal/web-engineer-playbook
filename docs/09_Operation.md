# 09. 運用・監視

---
## 9.1. モニタリング・アラート
- [ ] **OPS-001:** モニタリングの4つのゴールデンシグナル（レイテンシー, トラフィック, エラー, 彩度）を説明できる。
- [ ] **OPS-002:** USEメソッド（Utilization, Saturation, Errors）とREDメソッド（Rate, Errors, Duration）を説明できる。
- [ ] **OPS-003:** SLI（サービスレベル指標）、SLO（サービスレベル目標）、SLA（サービスレベル合意）の違いを説明できる。
- [ ] **OPS-004:** アラートの閾値設定の難しさ（アラート疲れ）を説明できる。
- [ ] **OPS-005:** 監視ツール（Datadog, CloudWatchなど）を使い、CPU使用率のメトリクスをグラフで表示する。
- [ ] **OPS-006:** CPU使用率が80%を5分間超えたらアラートが飛ぶ、という設定を監視ツールで行う。
- [ ] **OPS-007:** ホワイトボックスモニタリングとブラックボックスモニタリングの違いを説明できる。
- [ ] **OPS-008:** アプリケーションのカスタムメトリクス（例: ユーザー登録数）を送信するコードを記述する。

---
## 9.2. ロギング
- [ ] **OPS-009:** ログレベル（DEBUG, INFO, WARN, ERROR, FATAL）の使い分けを説明できる。
- [ ] **OPS-010:** 構造化ロギングのメリットを説明できる。
- [ ] **OPS-011:** 構造化ログ（JSON形式）を出力する。
  <details>
  <summary>手を動かす</summary>
  - 任意のロギングライブラリを使い、`{ "level": "INFO", "message": "User logged in", "user_id": 123 }` のようなログを出力するコードを記述する。
  </details>
- [ ] **OPS-012:** ログにトレースID（リクエストID）を含める重要性を説明できる。
- [ ] **OPS-013:** ログを収集・検索するためのツール（Fluentd, Elasticsearch, Lokiなど）を挙げられる。
- [ ] **OPS-014:** ログに出力してはいけない情報（個人情報、パスワード、クレデンシャルなど）を説明できる。
- [ ] **OPS-015:** アプリケーションログ、アクセスログ、スロークエリログの違いを説明できる。

---
## 9.3. 分散トレーシング
- [ ] **OPS-016:** 分散トレーシングが解決する課題（マイクロサービスにおけるリクエストの追跡）を説明できる。
- [ ] **OPS-017:** トレース、スパン、コンテキスト伝播の概念を説明できる。
- [ ] **OPS-018:** OpenTelemetryの役割を説明できる。
- [ ] **OPS-019:** JaegerやZipkinなどの分散トレーシングシステムの役割を説明できる。
- [ ] **OPS-020:** 簡単なAPI呼び出しにトレースを計装（instrumentation）する。

---
## 9.4. 障害対応
- [ ] **OPS-021:** 障害発生時の一次対応（切り分け、影響範囲の特定、関係者への連絡）をシミュレーションできる。
- [ ] **OPS-022:** ログやメトリクスを見て、障害の原因を調査する。
- [ ] **OPS-023:** ワークアラウンド（応急処置）と恒久対応の違いを説明できる。
- [ ] **OPS-024:** ポストモーテム（障害ふりかえり）の目的を説明できる。
- [ ] **OPS-025:** ポストモーテムに記載すべき項目（タイムライン、根本原因、再発防止策）を挙げられる。
- [ ] **OPS-026:** 「なぜなぜ分析」を使い、障害の根本原因を深掘りする。
- [ ] **OPS-027:** On-call（オンコール）体制について説明できる。
- [ ] **OPS-028:** SRE（Site Reliability Engineering）の役割を説明できる。
- [ ] **OPS-029:** エラーバジェットの概念を説明できる。
- [ ] **OPS-030:** カオスエンジニアリングの目的を説明できる。
