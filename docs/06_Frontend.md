## FE-001 状態管理 (State Management)

### ゴール

コンポーネントの状態（State）とプロパティ（Props）の違いを理解し、Reactの`useState`フックを適切に使える。

### 完了条件

- [ ] `artifacts` フォルダに成果物を作成する
  - [ ] `README.md`
  - [ ] `anki.csv`
  - [ ] `sample/`

### 実務での思考プロセス

- このデータは**State**か**Props**か？
  - State: コンポーネント内で管理・更新され、画面の再描画を引き起こすデータ
  - Props: 親コンポーネントから渡される読み取り専用のデータ
- `useState`の初期値は適切か？
- 状態の更新は、必ず**セッター関数** (`setCount`など) を使っているか？（直接`state`を書き換えていないか？）
- 状態は本当にこのコンポーネントが持つべきか？ 親に**リフトアップ**する必要はないか？
- 複数のコンポーネントで共有される状態か？（その場合、グローバルな状態管理を検討）

## FE-002 リアクティビティ

### ゴール

Reactにおいて、どのような変更が画面の再描画（リエンダリング）を引き起こすかを説明できる。

### 完了条件

- [ ] `artifacts` フォルダに成果物を作成する
  - [ ] `README.md`
  - [ ] `anki.csv`
  - [ ] `sample/`

### 実務での思考プロセス

- 再描画のトリガーは何か？
  1.  コンポーネント自身の**State**が更新されたとき
  2.  親コンポーネントから渡される**Props**が変更されたとき
  3.  親コンポーネントが再描画されたとき
- なぜ意図しない再描画が発生しているのか？
- 再描画のパフォーマンスを最適化するにはどうすればいいか？ (`React.memo`, `useCallback`, `useMemo`)
